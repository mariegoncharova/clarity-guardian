# Sample Retro Report

## What Slowed The Team Down

- Tasks without acceptance criteria produced unclear QA handoff.
- Reopened tasks often had missing edge cases.
- Payment-related work created delivery risk because error states were under-specified.
- Long time in `In Progress` and `Testing` pointed to bottlenecks before release.

## Example Tasks To Discuss

| Task | Signal | Retro Question |
| --- | --- | --- |
| RETRO-101 | Reopened after testing | Which payment edge cases should be mandatory in future tasks? |
| RETRO-105 | Large scope, weak formulation | Should catalog filter work be split before planning? |
| RETRO-107 | Missing expected result | What localization and fallback details should be part of the template? |

## Next Sprint Improvements

- Require acceptance criteria before a task enters development.
- Add reproduction steps for bugs.
- Split broad UX tasks into smaller testable changes.
- Track external dependencies before sprint commitment.
